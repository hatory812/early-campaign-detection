# 実験計画書: ノード数・エッジ数だけを入力した GCN

## 検証する問い／仮説
GCN (現行の 900 次元ノード特徴) は、ノード特徴を N・E だけに置き換えた GCN より Accuracy が高い
(= GCN はグラフの規模以上の情報を使えている)。

## この結果で決めること
GCN が規模以上の情報を使えているかを確定し、今後も GCN を主役に t_w 掃引を続けるかを判断する。

## 前提として固定するもの
- データ: `/hss01/A.hattori/rww_all_graphs_minimized/<t_w>min`、t_w = 0〜60 分
- モデル・学習設定: 20260805 の実験と同じ (GCN 2 層、hidden_dim 128、lr 0.0001、100 エポック、バッチ 32、mean pooling)
- 分割: seed 0〜4 の 5 分割 (20260805 と同じテスト集合になることを確認済み)
- 指標: Accuracy (GCN は予測ラベルしか保存していないため)
- 比較相手: 20260805 の既存結果 (再実行しない)

## 上限
- 検証実験: 1 個 (N・E だけの GCN を t_w = 0〜60 分で実行)
- 計算時間: 12 時間以内
- 期限: 次のゼミまで (日付未確定)

## 範囲外
- 900 次元の特徴に N・E を足す条件
- 確率の保存と AUROC での比較
- ハイパーパラメータの調整、他の GNN

## 出力

### 目的
ノード特徴から内容と構造埋め込みを取り除き、規模 (N・E) だけを与えた GCN を作る。
これを現行の GCN と同じ分割で比べ、現行の GCN の精度のうち規模で説明できない部分があるかを調べる。

### 仮説と予測
- **支持**: 5 分割で平均した「Accuracy(現行 GCN) − Accuracy(NE-GCN)」が明確に正になる。
  → GCN は規模以上の情報を使っているので、GCN を主役にした掃引を続ける。
- **不支持**: 差が 0 付近か負になる。
  → 現行の GCN の精度は規模だけで出せるので、規模の対照を前提にした研究の立て方を検討する。

### 手順
1. **実装**: `--size_only` (既定 0) を追加する。1 のとき、各ノードの特徴を
   `[log(1+ノード数), log(1+エッジ数)]` (グラフ内の全ノードで同じ値) にする。変更箇所は「変更箇所」の節を参照。
2. **確認**
   - t_w = 1 分で 1 回実行し、ノード数・エッジ数が
     `results/20260915_エッジ発生時刻集中の仮説検証/features/1min.csv` の値と全 307 件で一致するかを確かめる。
   - 所要時間を測る。61 点で 12 時間を超える見込みなら、t_w を 0, 1, 2, 5, 10, 20, 60 分の 7 点に減らす。
3. **本実行**: `--size_only 1` で t_w = 0〜60 分を実行する。
   出力先は `results/<YYYYMMDD>_GCNにノード数とエッジ数だけを入力/`。
4. **集計**
   - 各 t_w・各 seed で、現行 GCN と NE-GCN の Accuracy の差を計算する。
   - 現行 GCN の出力が無い 8 点 (16, 18, 22, 28, 30, 31, 32, 40 分) は比較から除く。
   - 参考として、ロジスティック回帰 NE の Accuracy も同じ図に並べる。

### 判定基準
1. seed ごとに、比較できる t_w 全体で差を平均し、5 個の値を得る。
2. その 5 個の平均と 95% 信頼区間 (t 分布、自由度 4) を出す。
   - 区間の下端が 0 より上 → 支持
   - それ以外 → 不支持
